# 02 Renderer Vulkan

## Renderer Goal

NovaCore uses Vulkan as its primary graphics API and is optimized for deterministic performance, high frame rates, and scalability rather than maximum visual complexity. The renderer is designed around explicit resource ownership and minimizes hidden state.

The initial milestones focus on correctness and stability before advanced rendering techniques. Every frame should remain debuggable and reproducible.

## Design Principles

* Rendering is presentation only and never owns gameplay state.
* The RenderWorld is a read-only extraction of ECS state.
* CPU asset loading and GPU resource creation are separate phases.
* GPU resources are immutable except through explicit upload commands.
* Draw submission should minimize pipeline and descriptor changes.
* Renderer failures must never compromise dedicated server execution.
* Client launches may require Vulkan explicitly so legacy debug renderers do not mask backend failures.

## Backend Layers

* Renderer API
* RenderWorld extraction
* VulkanDevice
* Swapchain
* Frame Context
* RenderGraph
* GPU Resource Manager

* Material System
* Pipeline Cache

Each layer owns only its own resources and communicates through explicit interfaces.

## RenderWorld Extraction

Before rendering, gameplay state is converted into a presentation-only structure.

Extraction includes:

* Visible transforms
* Mesh references
* Material handles
* Camera state
* Lighting state
* Debug primitives
* UI commands

Rendering never reads ECS data directly during draw submission.

## CPU → GPU Asset Flow

All mesh assets follow the same pipeline:

```
GLB / glTF
    ↓
Importer
    ↓
CPU Mesh Representation
    ↓
Validation
    ↓
Staging Buffer
    ↓
vkCmdCopyBuffer
    ↓
Device Local Vertex Buffer
    ↓
Renderable GPU Handle
```

CPU mesh data may be released after successful upload unless explicitly retained for tooling.

## Frame Lifecycle

Every rendered frame executes in the following order:

1. Wait for current frame fence.
2. Acquire swapchain image.
3. Reset per-frame allocators.
4. Process pending GPU uploads.
5. Extract RenderWorld.
6. Perform visibility culling.
7. Build render graph.
8. Record command buffers.
9. Submit graphics queue.
10. Present swapchain image.
11. Schedule deferred destruction.

## Frames In Flight

Support two or three concurrent frame contexts.

Each frame owns:

* Fence
* Command pool
* Primary command buffer
* Descriptor allocator
* Temporary upload allocations
* Deferred destruction queue

Resources must never be destroyed until all referencing frames have completed.

## Swapchain Recreation

Window resize triggers:

* Device idle
* Destroy framebuffers
* Destroy image views
* Recreate swapchain
* Recreate dependent resources
* Resume rendering

Application state must survive swapchain recreation.

Current implementation:

* Window resize and pixel-size events refresh the platform window extent.
* Swapchain acquire and present paths detect out-of-date/suboptimal presentation.
* Swapchain image views, render pass, depth resources, framebuffers, world pipelines, and UI primitive pipelines are recreated as one dependent-resource group.
* Submitted frames, skipped frames, recreate count, swapchain readiness, swapchain size, last world box/mesh/line counts, and last UI rect/line/text counts are exposed through renderer backend stats for game-side diagnostics.
* The sky pass is camera-oriented and renders a configurable sun disc, atmospheric haze, horizon response, and light procedural cloud breakup.
  Its world-space ray basis shares the world camera's vertical FOV, swapchain
  aspect, yaw/pitch/roll and Vulkan projection Y flip. Camera translation is
  omitted from sky rays. `RenderWorldLighting::sunDirection` points from the
  shaded surface toward the sun; both diffuse lighting and the sky disc consume
  this same normalized direction. It is not the direction in which photons travel.
  `RenderSky::horizonHeight` remains an artistic gradient control, not a screen
  coordinate or a replacement for the world horizon. The sky push block is
  exactly 128 bytes and needs no descriptor or GPU-resource lifetime changes.
* Soft sun-aligned contact shadows are submitted as a dedicated blended depth-tested pass and reported through backend frame statistics.
* World meshes upload cooked UV0 data and use per-fragment metallic/roughness response with deterministic micro-surface variation.
* Viewmodel meshes use an isolated short-range projection and depth clear so held weapons and arms do not disappear into world geometry.

## Phase 4 visual targets and evidence

### Physical camera chirality (Phase 5)

glTF scene coordinates are right handed. Its camera lens faces local -Z;
camera-local +X describes screen right. See the
[Khronos glTF coordinate/camera specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).
Imported geometry and node transforms retain that scene convention.

NovaCore keeps its logical look-direction API: zero yaw/pitch looks toward
world +Z, positive yaw points toward +X, and positive pitch looks up. The
physical camera frame now uses `(right, up, backward)` as a proper rotation
with determinant +1, with `backward = -forward`. At zero yaw/pitch, physical
right is world -X. View rows are right/up/backward; the standard RH perspective
uses clip W = -view Z, Vulkan depth 0..1 and the existing framebuffer Y flip.
Sky rays consume the same physical camera basis.

The previous +Z-depth camera displayed right-handed scene geometry with the
opposite horizontal chirality. A proper offline Y180 character rotation cannot
repair that view/content mismatch. Correcting the camera preserves the
anatomical sides and asymmetric thumb/index geometry without changing meshes,
bone identities, sockets, normal transforms, asset scales or winding.

Consumer migration is required before changing a production game pin:
camera-relative placements/strafe must use the physical right basis, and
human-right mouse/gamepad yaw input must account for logical positive yaw now
turning physically left. Existing game-world look directions remain unchanged
for the same supplied yaw/pitch. Input policy belongs to Nemisis. Pixel-space
UI geometry and its final overlay pass do not use this 3D camera transform.

The independent CPU fixture projects actual right/left wrists, medial thumbs,
distal index points and front/rear markers through a proper source Y180
rotation, comparing them with a separate standard glTF -Z-camera formula.
It also checks both camera yaw directions, view determinant, poles/roll and
existing sky/world/FOV/aspect/depth contracts. The untouched previous camera
fails 112 assertions with this fixture; the RH camera passes the standalone
suite. Full engine/cross-repo/Vulkan and visual gates are recorded separately.

Future shadow receivers can still reconstruct world coordinates from clip
X/Y/W and the shared physical ray basis: visible clip W remains the positive
logical forward distance. The isolated R2 work is held behind this camera/game
migration gate; no shadow map or texture feature is claimed by this fix.

### Instance normal foundation (R1)

The world mesh vertex shader applies the render instance inverse transpose to
normals: for `T * Ry * Rx * Rz * S`, this is the unit rotation quaternion times
the reciprocal scale. Normals and key/fill directions meet in world space and
the fragment shader renormalizes interpolated normals. Instance translation
does not affect shading; rotating a mesh by 180 degrees changes the surface's
orientation toward the fixed world light. A singular/non-finite instance scale
or non-finite rotation skips the draw with a once-per-session diagnostic.

The push block remains 128 bytes without adding GPU buffers/descriptors:
WVP and RGBA retain float precision, rotation/reciprocal scale use floats,
the two unit light directions use octahedral unorm16 pairs, and six bounded
light/material factors use unorm16 pairs (absolute scalar error at most
approximately 7.7e-6). CPU tests bound the directional error below 0.01 degree.
Invalid non-finite scalar factors become zero before integer conversion;
finite values preserve their existing clamp intervals.

Only the submitted `RenderMesh3D` instance transform is applied here. The glTF
importer or CPU skinning has already produced input vertices/normals; no node
transform is applied again by this change. An independent existing importer
defect remains: `GltfDocument.cpp::applyNodeTransform` currently transforms
baked normals with the linear node matrix instead of its inverse transpose.
R1 cannot repair those already incorrect inputs. A separate importer followup
needs a slanted triangle with mixed parent/child TRS, nonuniform scale and a
normal perpendicular to both transformed tangents, plus preserved skin/node
behavior. Identity-instance preservation tests do not establish importer
correctness under baked nonuniform scale.

The current material shader still uses a fixed world view vector for specular
and rim approximation. Camera-relative specular/Fresnel, real texture normal
maps, BRDF/IBL, cast shadows and reflections remain separate R2-R4 work; R1
does not claim physically based or complete material response.

## Phase 5 bounded directional shadow map (R2)

`RenderFrameInfo::directionalShadows` is opt-in and defaults to disabled. Disabled
frames allocate no shadow images, descriptors or pipelines. A valid enabled
frame lazily creates one depth-only pass and one sampled depth map per in-flight
slot. Both static meshes and the current slot's CPU-skinned vertex buffers cast
onto world boxes and meshes. This is one camera-centred directional map, not
cascades, point-light shadows, transparency shadows or world-wide coverage.

Settings accept resolutions 256/512/1024/2048, receiver distance 1..150 metres and
finite normalized depth/slope-bias values 0..0.05. Invalid settings, sun or camera
data retain baseline world rendering with a bounded diagnostic. The map covers
a receiver sphere of radius `distance`; visibility fades to fully lit over
0.8..1.0 times that radius. Outside the map or light-depth extrusion, surfaces
are fully lit. Casters are conservatively culled against the light frustum, not
the receiver sphere: an off-camera caster toward the sun can still occlude it.
The finite extrusion extends two map half-extents in each light-depth direction.

Light-space XY texel snapping and a one-texel border stabilize translation while
covering the entire receiver sphere. A 3x3 comparison PCF kernel filters the
sampled depth; raster depth bias plus configurable receiver depth/slope bias
reduce acne. Bias values require scene/device validation to avoid detached
shadows and lost small details. Ambient/fill remain lit; visibility attenuates
the sun's diffuse/specular terms. Existing procedural material variation and
fixed view vectors remain separate R3/R4 work.

`castsShadow` and `receivesShadow` are independent extraction flags on boxes and
meshes. Camera-attached first-person meshes in the World layer require explicit
opt-out from the consuming game; layer membership alone does not identify them.
Legacy ViewModel geometry stays on its existing camera/pipeline and never casts.
The existing contact-shadow approximation remains separately configurable and
must be compared with it disabled when evaluating the real map.

The existing 128-byte world push blocks remain unchanged. A private 160-byte
std140 UBO reconstructs mesh world positions from the actual shared RH camera
clip coordinates. Two aligned UBO entries per slot support receiver opt-out.
Depth images use sampled D32 float, with sampled D16 fallback, nearest comparison
sampling and a white border. No stencil or UI descriptor layout is shared.
Preparation follows the existing slot fence and dynamic vertex update. The
depth pass precedes the world pass in the same command buffer; full-frame
read-to-depth-write and depth-write-to-fragment-read dependencies cover image
layout transitions. These are not framebuffer-local BY_REGION dependencies.
Resolution changes wait for device idle before replacing all slot resources.
Swapchain teardown destroys receiver pipelines/layouts before shadow resources.
The UI adapter retains its existing prepare, last-in-pass record and teardown.
See the [Vulkan render-pass specification](https://docs.vulkan.org/spec/latest/chapters/renderpass.html).

## Phase 5 R3 opaque glTF texture candidate

`RenderFrameInfo::materialTexturesEnabled` defaults to false. Enabling it
selects real image-backed world-mesh variants for base color, metallic/roughness,
normal and emissive maps. Boxes and the legacy ViewModel path retain their
existing rendering. This is an opaque material slice, not completed PBR,
transparency, reflections or environment lighting.

The generic CPU importer now retains immutable shared PNG/JPEG encoded payloads,
image/texture/sampler linkage, UV0/UV1, independent per-map UV selection,
normal scale, alpha metadata and emissive strength. External percent-encoded
file URIs, data URIs and GLB bufferViews use the existing URI/buffer path.
Invalid indices, sampler enums and unsupported requested UV sets report import
errors. KHR_texture_transform offset/scale/rotation/UV override metadata is
retained; its material receives an explicit renderer fallback in this slice.
This preserves the existing NCAR asset's default-OFF loadability. BLEND/MASK
materials also receive an explicit opaque factor fallback: alpha-aware depth,
shadow casters, sorting and blending remain open. UV sets beyond 1 used by a
supported map are rejected rather than silently replaced with UV0.

The private decoder is unchanged upstream stb_image 2.30, pinned to the official
[nothings/stb commit](https://github.com/nothings/stb/tree/2c980bb59875b0d32144a71867fbdebb2f77cd20),
with the MIT alternative and exact file hashes under third_party/stb. Only
PNG/JPEG memory decoding is compiled, in one private translation unit. Encoded
images are limited to 64 MiB each / 256 MiB per scene / 512 images. Decoding
limits either axis to 8192 and the image to 16 million pixels. One image is
decoded at a time; decoder/output copies or output/staging may briefly total
128 MiB for the largest permitted RGBA image, plus the decoder's working memory.
Registration with the flag OFF
performs no pixel decoding, material image upload or descriptor allocation.

Base-color/emissive maps use Vulkan sRGB image formats; metallic/roughness and
normal maps use linear UNORM. MR uses green roughness / blue metallic multiplied
by the factors once. Normal maps use a derivative tangent frame from the
selected UV set and actual reconstructed world positions; no image-name axis
corrections are applied. Authored wrap/min/mag/mipmap filters are honored with
full generated mip chains when requested. Unsupported format/blit capability
causes a diagnostic fallback. Shader output is manually sRGB encoded only on
supported UNORM SDR presentation; an sRGB attachment performs hardware encoding.
The old lighting/tone curve and fixed specular view vector remain R4 work.

Material descriptors use private set 1 (frame UBO 80 bytes, material UBO 48
bytes, four image/samplers); R2 retains set 0 and its 160-byte block. World push
constants remain 128 bytes. UV1 extends the mesh vertex stride to 40 bytes in
both world and depth pipelines, including safe-slot dynamic updates. No public
Vulkan types are exposed. CPU skinning/subset copies share encoded payloads;
the animation bridge's existing whole-mesh copy preserves the appended data.

The device-lifetime material owner survives swapchain recreation. Its immutable
per-material descriptors are created once per mesh residency and frame slot;
frame UBO writes follow the existing safe-slot fence. Image identity includes
encoded content hash, byte equality, color space and compatible mip coverage,
so separately loaded body/arm/companion subsets can share images. Weak cache
entries do not keep retired meshes resident. Image allocations reserve their
actual Vulkan memory requirements against min(1 GiB, largest local heap / 4),
with rollback on upload/registration failure and deferred mesh retirement.
Counters expose resident source images/bytes, budget/rejections and actual
textured/fallback draws. A requested boolean is never readiness evidence.
The first upload uses the existing graphics queue with a synchronous idle wait;
asynchronous streaming/performance optimization remains open. UI descriptors,
pixel geometry, last-in-pass order and teardown are unchanged.

A successful upload submit followed by an unconfirmed idle wait retains its
command, staging buffer and image in one inline pending entry. No further image
upload is started; preparation retries completion even when texturing is OFF.
Only SUCCESS or DEVICE_LOST permits release. Before any backend recreation or
teardown destroys children, a private guard retries three times; persistent
unconfirmed completion terminates without unwinding the pending resources.
See [queue completion](https://docs.vulkan.org/refpages/latest/refpages/source/vkQueueWaitIdle.html)
and [command-buffer lifetime](https://docs.vulkan.org/refpages/latest/refpages/source/vkFreeCommandBuffers.html).
This is a source-reviewed lifetime fix; actual GPU OOM fault injection remains
open. Unsupported materials also retain finite nonnegative emissive factors in
the real fallback UBO, covered by the CPU regression test.

CPU tests cover exact PNG channels/straight alpha/row order, JPEG tolerance,
invalid/truncated/oversized inputs, three image source forms, normalized UV1,
texture/sampler linkage, material metadata, unsupported transforms/alpha,
image sharing through two actual skinning frames, content identity and budget
rollback/overflow. The original animation import test's texture-index-2 contract
remains; its previously dangling texture reference now has a valid embedded PNG
and three texture records. No assertion was removed or weakened.

## Phase 5 R4 bounded direct material light candidate

The opt-in MATERIAL_TEXTURES fragment path now derives the surface-to-eye
direction from the existing frame eye and actual world position. It evaluates
isotropic GGX distribution, height-correlated Smith visibility, Schlick Fresnel
and Lambert diffuse for the existing sun/fill directions. The dielectric/metal
mixture uses dielectric F0 0.04, base-color metal F0, squared perceptual
roughness, and zero metal diffuse. Its formula references are the official
[glTF Appendix B at 521a91d](https://github.com/KhronosGroup/glTF/blob/521a91d491f02bb7db7d445b35f591d09d2a64ce/specification/2.0/Specification.adoc#appendix-b-brdf-implementation)
and [Khronos BRDF reference at 74aaf40](https://github.com/KhronosGroup/glTF-Sample-Renderer/blob/74aaf40853dd92c554101e4f9f17ba1a13d12367/source/Renderer/shaders/brdf.glsl).
This is a direct single-scattering approximation, not an exact energy-conserving
or complete environment/reflection model.

The existing 0.04 perceptual roughness floor remains a numerical approximation.
Safe normalization rejects zero/nonfinite eye and half vectors; negative/zero
view/light cosines produce no direct response. An equivalent GGX denominator
avoids cancellation near the sharp peak. The incident cosine is folded into
Smith visibility before multiplication, avoiding an unnecessary grazing-angle
intermediate overflow. Sharp ideal directional highlights can still be very
bright before the existing tone curve; antialiasing/filtering remains separate.

Sun incoming strength remains the existing unitless 1-ambient control; fill uses
its existing intensity. R2 visibility attenuates the whole direct sun response,
including diffuse and specular; it does not shadow fill, ambient or emission.
Ambient stays a documented nonmetal diffuse approximation. The old artistic
rim/specular scalars remain active in the legacy path and are unused by this
opt-in BRDF. Sky exposure/sun intensity do not become calibrated mesh radiance.
Existing sampled MR/normal/UV, factor fallback, emissive-before-Reinhard and
single sRGB output conversion contracts are unchanged. No new renderer API,
UBO, push layout, descriptor, upload, pipeline owner, asset or queue is added.

The new private GLSL include is the only additional CMake shader dependency.
The complete fresh SDK compile/spirv-val gate passes all 27 modules: all
23 baseline modules and both textured vertex modules are byte-identical to
frozen R3; only the two textured fragment modules change. At exact runtime
92394956a26d74dd18c9bb2e00292bc02ea169ad, complete new-directory Release
headless engine/server/sandbox and all 9/9 CPU suites pass (1.38 seconds).
The complete separate actual SDL3/Vulkan engine/server/sandbox build/install
also passes. Hosted checks, the combined consumer and real GPU numerical/visual
gates remain separate.

Independent CPU design calculations use Smith's lambda form rather than the
shader's visibility expression. For unit front-facing light/view, base red 0.5
and roughness 0.5, the reference cosine-weighted red response is 0.2037183272
for dielectric and 0.6366197724 for metal, matching their analytic values.
Swapping light/view preserves the BRDF after dividing out the incident cosine.
Rough metal has a broader lobe than sharp metal, and the grazing/zero-vector
reference cases remain finite. These are reference calculations only: no C++
formula copy or source-pattern check is registered as a shader execution test.
Actual GPU evaluation/readback is still open.
Comparisons must account for the existing UNORM16 roughness/metallic packing.

After the combined R3 gate, matched captures should hold light/material/exposure
fixed while moving the eye: highlights must follow eye and roughness, not world
Z. Sweep dielectric/metallic endpoints and roughness, camera yaw/pitch/roll,
180-degree mesh rotation, nonuniform scale, normal maps, R2 shadows and SDR
presentation formats; preserve UI output. Existing M01/M02 references motivate
surface response differences; P01/P02 reflections remain future work. Very dark
metals without environment illumination are a limitation of this direct-only
step. IBL, probes, material extensions, transparency, two-sided normal policy,
baked nonuniform source normals and HDR/exposure redesign are outside scope.

## R5a: opt-in scene-global specular sky IBL

`RenderFrameInfo.skyEnvironmentReflectionsEnabled` is appended and defaults to
false. It requires the existing material texture path, a valid perspective
camera, SDR attachment and an enabled finite procedural sky with its actual
graphics pipeline available. A missing/failed sky pipeline suspends generation
and uses R4, without resetting failed-attempt limits. This bounded step
adds global sky reflections to the R4 material BRDF; it supplies no local-object
reflections, transmission/glass, diffuse irradiance, reflection probes or LOD.

The immutable source reproduces the actual sky's world-direction gradient,
horizon height/power, haze and directional cloud function **before** display
mapping. RGB inputs are linear, finite, nonnegative and bounded to 64; values
outside that slice limit explicitly fall back to R4. Horizon/power/haze/cloud
and exposure use exactly the existing sky clamps. Sky exposure multiplies this
radiance once. The sky's exponential display mapping is excluded; material
lighting still uses its existing Reinhard and single sRGB conversion. The entire
direct sun disc/glow term is excluded to avoid adding R4 sun lighting twice.
Camera position/yaw/pitch/roll and sun motion cannot invalidate this sun-free
source. The source is a global distant sky, so objects and nearby covers cannot
appear in these reflections or occlude this environment term.

Fixed CPU generation produces a 128-square six-face RGBA32F cube with eight
GGX-prefiltered roughness mips, 64 Hammersley samples per filtered texel, and a
64-square RG32F BRDF LUT using 128 samples per texel. The LUT integrates the
same height-correlated Smith GGX/Schlick response as R4. The shader evaluates
prefiltered radiance along `reflect(-V,N)` at roughness times maximum mip,
multiplied by the split-sum `F0*A+B`. No image codec, third-party asset,
additional queue or new renderer framework is involved. The established
[Khronos sample IBL path](https://github.com/KhronosGroup/glTF-Sample-Renderer/blob/74aaf40853dd92c554101e4f9f17ba1a13d12367/source/Renderer/shaders/ibl.glsl)
and [Khronos IBL sampler](https://github.com/KhronosGroup/glTF-IBL-Sampler)
provide the primary method references. This slice does not include their
multiple-scattering compensation or additional material lobes.

The source must match on two consecutive prepares. Attempts are separated by
at least two seconds, including failures. Successful matching sources never
regenerate. Transient failures get at most three attempts per source activation;
after that R4 remains until a source change or explicit feature/source off/on.
Pending-upload or camera suspension only breaks consecutive observation and
cannot reset/bypass that attempt limit. A changed/invalid source immediately
stops using a cached map that does not match. There is no per-frame generation
or retry. The first LUT is reused across source changes. Raw generated data is
2,129,888 bytes with LUT (under 2.1 MiB),
and work/sample counts are fixed. Generation and synchronous upload can stall
the opt-in/configuration frame; runtime logging records their combined CPU
elapsed time and actual shared image residency. These logs are not GPU timings.

Float cube/LUT sampled-image and linear-filter capabilities, image dimensions,
mip/layer limits and image-format support are checked before generation.
Unsupported formats use R4 without a fake LDR/HDR substitute. All image memory
uses the existing actual `VkMemoryRequirements.size` budget with rollback;
`residentMaterialImageBytes` and budget/reject counters include environment
allocations and retained pending uploads. `residentMaterialImageCount` still
counts cached glTF source images. The last valid cube/LUT remain cached while
the feature is off, bounded to one of each plus at most one replacement/pending
upload. Old images/sets are replaced only after a successful graphics-queue
completion wait. A submitted upload with an unconfirmed wait retains its image,
staging and command in the existing pending owner, stops subsequent uploads,
and uses the existing early resize/shutdown completion guard. No UI or R2
descriptor/lifetime ownership changes.

Two additional fragment variants reuse the existing textured vertices and the
unchanged 128-byte push constants. Private global set 2 has exactly two sampled
bindings. Existing 80-byte frame UBO offsets stay intact; previously unused
parameters y/z at byte offsets 68/72 carry readiness/maximum mip.
`skyEnvironmentReflectionsReady` is true only when an indexed draw was actually
recorded with the matching sky pipeline/descriptors; its draw counter measures
those commands, not requested instances or proof of GPU execution.

The small initial gate passes the production CPU generator/contracts and all
29 compiled Vulkan 1.0 SPIR-V modules. All 27 existing modules are byte-identical
to frozen R4, including both textured fragments. The production CPU tests cover
world cube axes/shared edges, exact pre-tone sky poles/exposure, immutable
source rejection and rate limits, constant-radiance conservation at every mip,
finite LUT endpoints and roughness broadening. Their measured total was about
1.53 seconds on this machine; this includes two complete CPU cube generations
and is not a GPU/real-frame timing. Full engine/hosted/consumer builds and actual
device sampling, validation layers, OOM injection, GPU numerical comparison and
visual/timing gates are still pending at this source handoff.

Matched future captures must hold geometry, material tint, lighting, camera and
exposure fixed while toggling R4/R5a. Neutral-tint metal/dielectric patches and
actual weapon materials should show the authored sky/ground directions,
eye-dependent Fresnel and broader rough reflections without arbitrary white
metal boosts. Check yaw/pitch/roll, 180-degree mesh rotation, nonuniform scale,
normal maps, R2 shadows, sky changes/off, resize and both SDR output formats;
the UI must remain stable. Reference S01
([clear sky](https://polyhaven.com/a/hausdorf_clear_sky)), S02
([sunset](https://polyhaven.com/a/bambanani_sunset)) and M02
([metal](https://polyhaven.com/textures/metal)) motivate sky orientation and
roughness contrast. No reference image is copied into assets. Historical
screenshots are not a matched baseline, and sky IBL cannot meet local-object or
glass aspirations in P01/P02. GPU/visual gates remain open while GUI is paused.

## Acceptance Criteria

The renderer is considered production-ready for its milestone when:

* Vulkan initializes successfully.
* A 3D greybox primitive scene renders through the Vulkan path.
* Swapchain recreation is stable.
* Meshes upload correctly into device-local memory.
* Camera movement updates without artifacts.
* Descriptor allocation remains leak-free.
* Multiple frames in flight execute correctly.
* Debug overlays and menu/HUD primitive UI coexist with world rendering.
* Dedicated servers continue functioning without renderer initialization.
